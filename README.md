# 智汇 ERP · 智能制造经营管理台

> 一个可直接演示的 ERP / MES 一体化管理后台作品集项目。面向一家 120 人规模、拥有自有产线的智能硬件制造企业，把**生产工单、设备运维、员工、客户、订单、库存与经营数据**收进同一个工作台。
>
> 纯静态前端 · 零框架 · 零依赖 · 零 CDN · 无构建步骤

**交付状态**：可运行　|　**技术栈**：HTML / CSS / ES6+　|　**生产依赖**：0　|　**数据存储**：localStorage

## 1. 业务背景

**深圳智汇智能制造有限公司**是一家约 120 人的智能硬件制造企业，主营 IoT 网关、边缘计算设备与工业传感器，拥有 **SMT 贴片线、整机组装线、测试包装线 3 条自有产线**，为智慧城市、工业物联与智能家居客户提供从 PCBA 到整机交付的一站式制造服务。

公司在「制造 + 经营」协同中存在三个典型问题：

- **生产黑箱**：销售订单下达后，工单进度、工序完成情况与报工数据分散在车间表格里，管理者无法在工作台看到在制进度与良率。
- **设备被动救火**：贴片机、回流焊、测试台等设备的状态、点检、保养与维修记录各自为政；设备一旦故障，哪些在产工单受影响需要人工核对，经常造成停线损失。
- **经营与制造脱节**：订单、库存与生产计划割裂，交付节点只能靠人工跟催，缺少可复用的产量、良率与 OEE 视图。

本项目模拟这套「订单 → 生产 → 设备 → 交付」的管理后台，重点演示：

1. 从经营总览到人员 / 客户 / 订单 / 库存维护，再到报表复盘的完整操作链路；
2. **生产端**：工单创建、工序进度、报工、停产 / 恢复与日产量趋势；
3. **设备端**：设备台账、状态看板、点检 / 保养 / 维修工单与 OEE 分析；
4. **生产与设备联动**：设备故障自动标记受影响工单并可一键暂停；报工产量同步计入设备今日 / 累计产量。

所有数据均为虚构的演示数据。

## 3. 功能清单

### 3.1 登录与全局框架

- 演示账号登录：`admin / 123456`，错误账号会给出内联错误提示。
- 登录后写入 `session` 到 localStorage，刷新保持登录；退出后清除会话。
- 左侧导航分为 **Overview / 制造运营 / Operations / System** 四组，共 **9 个一级页面**；窄屏下自动收为**底部图标导航**，内容区不产生横向滚动。
- 顶部全局搜索（按钮 / `/` / `Ctrl+K`）：聚合功能入口、员工、客户、订单、商品、**生产工单与设备**，支持方向键选择、Enter 打开、Esc 关闭；搜索到工单 / 设备时会直接定位并打开详情。
- 通知中心：根据低库存、待发货、待付款、**设备故障与受影响工单**实时生成通知，可全部标为已读并跳转对应模块。
- 导航角标：订单待发货数、库存预警数、**受影响工单数、故障设备数**。
- 用户菜单：返回工作台、系统设置、退出登录。
- 顶部深浅主题切换；主题偏好持久化，图表颜色随主题重绘。

### 3.2 工作台 Dashboard

- 4 个实时经营 KPI：本月销售额、本月订单数、客户总数、库存预警数。
- **生产与设备摘要**：在产工单进度列表（受影响工单整行红色高亮并带「受影响」标记）+ 设备状态分布环形图（运行 / 待机 / 故障 / 保养中计数）。
- 近 6 个月销售额趋势折线图（Canvas 自绘，含面积渐变、节点、最新值气泡、悬停提示）。
- 全部订单状态分布环形图（待付款 / 待发货 / 已完成 / 已取消，含中心总数与图例）。
- 待办事项：本地可勾选，进度条实时更新并持久化。
- 公司公告：生产 / 制度 / 品质 / 系统 / 行政分类、置顶、公告详情弹窗、全部公告归档。
- 经营简报一键导出 CSV（含销售、生产与设备指标）。

### 3.3 生产管理

**4 个生产 KPI**：在产工单数、本月计划达成率（按已开工工单口径）、本月良率、今日产量（含较昨日趋势）。

- **生产工单列表**：工单号 / 产品 / BOM 版本 / 计划数量 / 完成数量 / 产线 / 绑定设备 / 状态 / 计划交期 / 进度 / 操作。
  - 状态：待产 / 生产中 / 已暂停 / 已完工，支持状态 Tab 计数、关键词搜索、产线筛选、分页。
  - 绑定设备以彩色状态标签展示，故障设备为红色；受影响工单整行红色高亮并显示 **「受影响」** 标记；逾期交期红色提示。
- **新建工单**：选择产品后自动带出 BOM 版本与工艺路线，选择产线、勾选绑定设备（故障设备不可选）、填写数量 / 交期 / 优先级；工单号按 `WO-年月-序号` 自动生成，创建后进入待产状态。
- **报工**：输入本次完成数与不良数，实时预览报工后进度、良率与剩余数量；提交后更新完成数、不良数、工序进度与生产报表，达到计划数量时自动转为已完工。
- **工序进度**：每张工单包含 3–5 道工序（SMT 贴片 → 板级测试 → 整机组装 → 老化测试 → 包装入库等），在工单详情中展示每道工序完成状态与进度条，进度由累计完成数自动推导。
- **暂停 / 恢复 / 开工**：生产中可暂停（记录暂停原因），已暂停可恢复，待产可开工。
- **工单详情**：产品 / BOM / 产线 / 负责人、计划 / 完成 / 不良 / 良率 / 进度、逐道工序进度、绑定设备状态、报工记录时间线；设备故障受影响时详情顶部直接提示并可暂停。
- **生产趋势**：近 12 天日产量分组柱状图（良品产量 + 不良数量），按报工时间聚合，非独立假图表。
- **一键暂停受影响工单**：设备故障横幅中可一次暂停所有受影响的在产工单。
- 工单清单 CSV 导出（携带良率、设备、受影响标记）。

### 3.4 设备管理

**5 个设备 KPI**：设备总数、运行中、待机 / 保养、故障设备、平均 OEE。

- **设备状态看板**：按 3 条产线分组，每张产线卡显示运行数 / 平均 OEE / 负责人；设备卡片按状态着色（运行绿 / 待机灰 / 故障红 / 保养中琥珀），故障卡片带脉冲提示，卡片内展示今日产量与关联工单数。
- **设备台账**：设备编号 / 名称与类型 / 所属产线 / 状态 / 负责人 / 上次点检 / 关联在制工单 / OEE / 操作；故障行红色高亮，支持状态 Tab、关键词搜索、产线筛选、分页。
- **设备详情**：
  - 状态切换：运行 ↔ 待机 ↔ 故障 ↔ 保养；切换到故障会自动生成待派工维修工单，切回运行会自动完成维修中工单。
  - 今日产量 / 累计产量 / OEE / 稼动率四项指标（产量由该设备的报工记录聚合）。
  - 关联在制工单列表：显示状态、进度、交期；受影响工单可直接暂停或跳转工单明细。
  - 维修工单：新增报修（故障现象 / 优先级 / 描述）、派工、完成维修。
  - 保养计划与保养记录：显示周期、下次保养日期、保养项；可执行保养并自动生成记录、顺延下次日期。
  - 点检记录：显示最近点检日志，可立即点检并更新上次点检日期。
- **图表**：设备状态分布环形图 + 产线平均 OEE 与目标（85%）对比柱状图。
- 设备台账 CSV 导出。

### 3.5 生产与设备联动（关键）

同一份 `db.workOrders` / `db.devices` / `db.productionReports` 数据源，跨页面实时一致：

1. **工单绑定产线与设备**：新建工单必须选择产线并绑定至少 1 台设备；设备状态直接展示在工单列表。
2. **设备故障 → 工单预警**：设备状态为「故障」时，绑定该设备且处于「生产中」的工单在工单列表 / 工单详情 / 工作台 / 设备详情中统一标记为受影响（红色高亮 + 「受影响」标签）；生产页与设备页均提供「一键暂停」入口。
3. **设备状态一致性**：设备 KPI、导航角标、状态看板卡片、环形图、台账、通知中心全部由 `db.devices` 实时聚合，口径一致。
4. **报工 → 设备产量**：报工时选择报工设备，产量计入该设备「今日 / 累计产量」与设备卡片；设备详情可看到关联工单的报工产出。
5. **维修闭环**：完成维修后设备恢复「运行」，受影响工单可恢复生产；维修状态（待派工 / 维修中 / 已完成）与设备状态联动。
6. **重置与持久化**：所有工单、报工、设备日志、保养与维修记录均写入 localStorage；系统设置一键重置后恢复完整制造版种子数据。
7. **数据升级兼容**：种子版本升到 v2，检测到旧版 v1 本地数据时自动重建为制造版完整种子，避免新模块读取空集合。

### 3.6 员工管理

- 25 名员工的表格：工号、姓名 / 邮箱、部门、职位 / 电话、入职日期、状态。
- 部门扩展为 9 个：运营、销售、生产、设备、品质、采购、仓储、财务、技术。
- 关键词搜索（姓名、工号、职位等）+ 部门筛选 + 分页（每页 8 条）。
- 新增员工：自动生成 `ZH0xx` 工号，必填项校验；编辑回填；删除二次确认。
- 员工名册 CSV 导出（导出当前筛选结果）。

### 3.7 客户管理

- 12 家客户的表格：公司名称、等级、行业 / 区域、联系人、电话、累计交易额、状态。
- 客户等级标签：A / B / C 三档视觉区分。
- 关键词搜索 + 等级筛选 + 结果计数。
- 新增客户：自动生成客户编号，维护等级、行业、联系人、地址等完整档案。
- 编辑 / 删除客户，删除带确认提示；客户清单 CSV 导出。

### 3.8 订单管理

- 20 笔订单：订单号、客户、销售单元、金额、状态、日期。
- 状态 Tab：全部 / 待付款 / 待发货 / 已完成 / 已取消，带数量角标。
- 关键词搜索订单号或客户名；点击订单行展开商品明细、收货信息、付款条件与履约进度。
- 彩色状态标签与履约进度节点；订单清单 CSV 导出。

### 3.9 库存管理

- 12 个 SKU：编号、名称、分类、当前库存、安全库存、单价、库存货值、状态。
- **低于安全库存整行红色高亮**，默认将预警商品置顶。
- 库存搜索 + 品类筛选；入库 / 出库弹窗实时预览操作前后库存与安全线差额。
- 出库数量超过当前库存时行内校验拦截；成功后立即更新表格、预警数、导航角标、顶部通知和 KPI。
- 库存流水写入本地数据；库存清单 CSV 导出。

### 3.10 报表中心

- 按月份（近 6 个月）+ 销售单元筛选，联动刷新汇总数据与柱状图。
- 4 个汇总 KPI：本期销售额、目标完成率、有效订单、平均客单价。
- Canvas 分组柱状图：实际销售额 vs 月度目标，含图例、悬停提示。
- 部门经营汇总表：负责人、目标、实际、完成率、订单数、合计行；自动生成经营洞察文案。
- 经营报表 CSV 导出。

### 3.11 系统设置

- 公司信息表单：名称、信用代码、行业、规模、联系人、电话、邮箱、官网、地址、简介；保存到 localStorage 并同步侧边栏公司名。
- 主题设置：浅色 / 深色两套主题，即时预览，刷新后保留。
- 数据管理：查看员工、客户、订单、商品、**生产工单 / BOM、设备 / 维修工单**数量与数据占用；导出完整 JSON 备份；一键恢复 25 位员工、10 张工单、13 台设备、5 个 BOM、12 家客户、20 笔订单与 12 个商品的初始数据（带二次确认）。

## 4. 技术栈

- **标记**：语义化 HTML5、内联 SVG symbol 图标（无外部图标库）
- **样式**：原生 CSS3，自定义属性（CSS Variables）、Flex / Grid、媒体查询、backdrop-filter、CSS 动画
- **逻辑**：ES6+（严格模式、IIFE、事件委托、模块 IIFE、同步数据流）
- **持久化**：localStorage（数据库 + 登录态 + 主题 + 通知已读状态）
- **可视化**：Canvas 2D 手写折线面积图、环形图、分组柱状图（DPR 适配 + tooltip + 动画）
- **工程**：无 npm 依赖、无构建步骤、无外部 CDN、无后端

### 外部网络访问

页面运行时不请求任何外部资源。UI 中的 `Created By Deerflow` 为指向 `https://deerflow.tech` 的品牌署名超链接，仅在点击时打开，不参与页面渲染。

## 5. 如何运行

### 方式 A：本地 HTTP 服务（推荐）

在 Windows PowerShell 中执行：

```powershell
cd "D:\新建文件夹\job\erp-demo"
python -m http.server 8902 --bind 127.0.0.1
```

浏览器访问：

```text
http://127.0.0.1:8902
```

### 方式 B：直接双击

直接双击 `index.html` 即可在 Chrome / Edge 中打开。已实测在 `file://` 模式下页面样式与脚本正常加载、登录与 localStorage 持久化可用、控制台无 JavaScript 运行时错误。

> 某些浏览器对 `file://` 下 localStorage 的限制更严格；如果发现数据没有保留，改用方式 A 启动本地 HTTP 服务即可。

### 建议环境

- Chrome / Edge 120+（其他现代浏览器亦可）
- 屏幕宽度 320px 至 1440px+

## 6. 演示路径建议

7. 员工 / 订单 / 库存 / 报表：搜索、筛选、行展开、出入库与图表联动。

## 10. 已知边界与可扩展方向

- **无真实后端**：登录校验和业务数据都在前端模拟，不能作为生产鉴权使用。
- **数据仅限本机浏览器**：清除浏览器站点数据或更换设备后，演示会回到初始种子数据；种子 v2 升级会重建旧版数据。
- **订单 / 商品 / 生产数据为演示数据**：金额、客户、物料、设备名称均为虚构，不对应真实企业。
- **可继续扩展**：工单排程与产能平衡、BOM 展开与物料需求计划（MRP）、工序扫码报工、设备 OEE 明细（可用率 / 性能 / 良率）、SPC 品质看板、角色权限、真实后端 API、导出 Excel / PDF 等。
